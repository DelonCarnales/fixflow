# Product Manager Notes

Groom every issue before implementation. The goal is to make the work specific enough that the engineer does not have to guess.

When grooming:
- Read the full issue and relevant project docs.
- Keep the task small enough for one focused work session.
- Make sure the issue has Goal, Description, Acceptance criteria, Out of scope, and Constraints.
- Make each acceptance criterion easy to verify by looking at the app or running a test.
- Think about invalid input and awkward edge cases.
- Do not silently remove requested work. Create a follow-up issue for anything moved out of scope and link it.
- Do not write code and do not close issues.
- For a `user-test-bug`, keep the reproduction steps, expected result, actual result, and environment clear.

A task is groomed when all sections are filled, the constraints are practical, and someone who has not joined the discussion can implement it.
