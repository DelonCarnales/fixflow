# Brainstorming Before Development

This file records the initial idea discussion before coding started.

## First idea
I considered making a repair management app for a small computer and laptop repair shop. It seemed useful and more interesting than a basic to-do list or habit tracker.

## Why FixFlow
A repair shop has a clear workflow: receive a device, record the problem, diagnose it, wait for parts if needed, repair it, and mark it ready for pickup. That gives the project real functionality without making it too advanced.

## Main idea
The app will let staff manage repair orders, customer and device details, repair status, and a simple spare-parts list. Customers can check an order status with an order number.

## Scope decision
I decided to keep the first version simple. I will not build online payments, SMS notifications, AI repair diagnosis, or complex staff permissions for the MVP.

## Development plan
The work will happen in stages: frontend with mockService, OpenAPI contract, backend with in-memory data, SQLite through an ORM, frontend/backend integration, then testing.
